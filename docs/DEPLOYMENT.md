# Deploying the free demo (Render + Vercel)

```
Browser ──https──► Vercel (React build)
   │                  │  /api/*  rewritten to Render (same origin → first-party refresh cookie)
   │                  ▼
   └──wss (direct)──► Render web service (Spring Boot, Docker) ──► Render PostgreSQL
```

Both have free tiers that need no card at the time of writing; check their pricing pages, since this changes.
Free Render services sleep after a period without traffic, so the first request after that is slow.

## 1. Push the code to GitHub

Everything below reads from your GitHub repository.

## 2. Backend and database on Render

1. Render dashboard → **New → Blueprint** → choose the repository. Render reads `render.yaml` and proposes a
   PostgreSQL database `rideshare-db` and a web service `rideshare-api`.
2. It asks for the values marked `sync: false`:
   - `CORS_ALLOWED_ORIGINS`: your Vercel URL, e.g. `https://rideshare-campus.vercel.app` (you can put a
     placeholder now and fix it after step 3).
   - `ADMIN_EMAIL` / `ADMIN_PASSWORD`: the first admin account.
3. Apply. The first build takes a while (Maven downloads dependencies inside Docker).
4. Open `https://<your-service>.onrender.com/actuator/health` → `{"status":"UP"}`.
5. Service → **Settings → Deploy Hook** → copy the URL. In GitHub: repository **Settings → Secrets and variables →
   Actions → New repository secret**, name `RENDER_DEPLOY_HOOK_URL`, paste the URL.

From now on a push to `main` runs the tests in GitHub Actions and, only if both jobs pass, calls the deploy hook.
(`autoDeploy` is off in `render.yaml` so a red build never goes live.)

Flyway creates the schema on first start (`V1` … `V4` migrations).

## 3. Frontend on Vercel

1. Edit `frontend/vercel.json`: replace `YOUR-RENDER-SERVICE` with your Render service name. Commit and push.
2. Vercel → **Add New → Project** → import the repository.
   - **Root Directory:** `frontend`
   - Framework preset: Vite (build `npm run build`, output `dist`), detected automatically.
   - Environment variable `VITE_WS_URL` = `wss://<your-service>.onrender.com/ws`
     (Vercel rewrites cannot carry WebSockets, so the socket goes straight to Render. It authenticates with the
     access token in the STOMP `CONNECT` frame, not with a cookie.)
   - Leave `VITE_API_URL` **unset**, so API calls go to `/api` on the Vercel domain and get rewritten.
3. Deploy, then put the final Vercel URL into `CORS_ALLOWED_ORIGINS` on Render (it is also the allowed WebSocket
   origin) and redeploy the backend.

Vercel deploys the frontend by itself on every push to `main`.

## 4. Check it

- Register with an institute email, reload the page: you should still be logged in (refresh cookie).
- DevTools → Application → Cookies: `rs_refresh` is `HttpOnly`, `Secure`, path `/api/auth`.
- Open a ride in two browsers; joining in one updates the seat count in the other (WebSocket).

## Production settings already in `render.yaml`

| Variable | Value | Why |
|---|---|---|
| `REFRESH_COOKIE_SECURE` | `true` | Cookie only over HTTPS |
| `FORWARD_HEADERS_STRATEGY` | `framework` | Rate limiting uses the client IP from `X-Forwarded-For` |
| `JWT_SECRET` | generated by Render | Never committed |
| `JWT_EXPIRATION_MINUTES` | `15` | Short-lived access token |
| `DB_POOL_SIZE` | `5` | The free database allows few connections |

Do not set `SPRING_PROFILES_ACTIVE=demo` on a public deployment (it seeds known passwords).
